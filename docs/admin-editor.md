# 홈페이지 직접 수정

관리자 주소: https://ipib.kr/admin/editor

기존 관리자 이메일과 비밀번호로 로그인합니다. 비밀번호를 채팅에 보내지 마세요.

1. 위쪽에서 페이지와 언어를 선택합니다.
2. ‘내용 선택’ 상태에서 문구 또는 사진을 클릭합니다.
3. 오른쪽에서 수정합니다. 사진은 파일 선택 후 확대·위치를 조절합니다.
4. ‘변경 내용 저장’을 누릅니다. 방문자가 새로고침하면 반영됩니다. GitHub 업로드나 재배포가 필요하지 않습니다.

홍콩·한국 지부 같은 탭은 ‘탐색 · 탭 선택’으로 먼저 연 다음 ‘내용 선택’으로 전환합니다. 다른 페이지 이동은 위쪽 페이지 목록을 이용합니다.

- 공통 머리말과 하단 수정은 현재 언어의 모든 페이지에 반영됩니다.
- 다른 언어는 각각 저장합니다. 자동 번역하지 않습니다.
- 수정한 항목은 오른쪽 목록에서 다시 선택하거나 기본 내용으로 복원할 수 있습니다.
- 사진 안에 이미 인쇄된 글자는 사진을 교체해야 바뀝니다.
- 소식 신규 등록, 게시 상태, 순서, 갤러리 추가는 기존 `/admin`에서 관리합니다.
- 사진은 JPG·PNG·WebP 원본 25MB까지 선택할 수 있으며, 브라우저에서 긴 변 1600px 이하의 WebP로 줄입니다. 서버 전송 한도는 4MB입니다. 투명 배경은 유지됩니다.
- 업로드 실패 시 문구 수정은 유지됩니다. 문구만 먼저 저장할 수 있습니다.
- 저장하지 않은 변경은 이 브라우저 탭의 임시 보관에 남습니다. 서버 내용이 다른 창에서 바뀌면 덮어쓰지 않고 안내합니다.

## 운영 구성

기존 Supabase `page_content` 테이블에 `visual:<페이지>` 키로 편집 내용만 저장합니다. 기존 페이지 상단·소식 데이터와 분리되며 새 DB 마이그레이션은 필요 없습니다. 기존 `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_EMAIL`, `ipib-media` 저장소 연결이 필요합니다. 값은 공개 저장소에 올리지 않습니다.

사진은 기존 `/api/admin/upload`를 통해 저장소에 저장되고 `/api/media/<자동 생성 ID>`로 표시됩니다. GitHub 이미지 Blob 업로드를 사용하지 않습니다.

화면 편집은 현재 페이지의 문구·사진에 적용됩니다. 요소의 위치와 원래 내용을 함께 확인하여 잘못된 위치에 적용하지 않습니다. 개발자가 페이지 구조나 원문을 크게 바꾸면 해당 항목은 다시 선택하여 저장해야 할 수 있습니다. 시각 편집 내용은 페이지가 열린 뒤 적용되며 검색 메타데이터 편집 기능은 포함하지 않습니다.

## 이미지 성능

`pnpm run build`는 먼저 `scripts/optimize-images.mjs`를 실행합니다. 원본을 유지하고 `public/optimized/assets/`에 화면 너비별 WebP를 생성합니다. 파일명에 원본 해시가 포함되어 사진 교체 시 오래된 캐시를 사용하지 않습니다. `ResponsiveImage`는 화면별 `srcset`을 사용하고 화면 아래 이미지는 지연 로딩합니다. 최적화 이미지 바이너리는 GitHub에 업로드하지 않고 Cloudflare 빌드에서 생성합니다.

검증: `pnpm run typecheck`, `pnpm run build`, `python scripts/verify-visual-editor.py`.
마지막 검증은 로컬 가상 저장소를 사용하며 실제 운영 계정 로그인·저장을 대신하지 않습니다.
